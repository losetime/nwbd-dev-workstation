# 诺维研发工作台 · 任务助手

通过项目里的脚本调用平台接口：**不要自己拼 curl、不要猜接口地址**。

## 什么时候用

- 用户问「我有哪些任务 / 今天要做什么 / 有没有逾期」
- 用户要看某个任务的详情、验收标准、执行时间线、已有产出
- 用户要「开始执行」某个任务（按绑定技能执行）
- 执行过程中要记录进展（做了哪一步、卡在哪）
- 任务做完了，要上传产出、提交结果
- 用户想看线上技能库里有哪些技能

## 怎么用

脚本在 skill 目录的 `scripts/` 下。以 OpenCode 为例，路径是 `~/.config/opencode/skills/nwbd-dev-workstation/scripts/`。

Windows（PowerShell）：

```powershell
$S = "$env:USERPROFILE/.config/opencode/skills/nwbd-dev-workstation/scripts/workstation.ps1"

& $S tasks                                  # 我的任务
& $S tasks -Status 进行中                    # 按状态过滤：未开始/进行中/已延期/已完成
& $S show <任务ID>                           # 任务详情 + 时间线
& $S start <任务ID>                          # 按技能开始执行（认领）
& $S log <任务ID> "接口联调完成 70%"          # 记录一条进展
& $S upload <任务ID> "D:\报告.pptx"           # 上传产出
& $S done <任务ID> -Summary "12 页 PPT 已完成" # 提交结果并完成
& $S skills                                  # 技能库列表
```

macOS / Linux：

```bash
S=~/.config/opencode/skills/nwbd-dev-workstation/scripts/workstation.sh

$S tasks
$S tasks --status 进行中
$S show <任务ID>
$S start <任务ID>
$S log <任务ID> "接口联调完成 70%"
$S upload <任务ID> ~/报告.pptx
$S done <任务ID> --summary "12 页 PPT 已完成"
$S skills
```

需要机器可读结果时加 `-Json` / `--json`，返回原始 JSON，便于你筛选字段。

## 令牌

脚本按这个顺序取令牌：

1. 参数 `-Token` / `--token`
2. 环境变量 `NWBD_WS_TOKEN`
3. 本地已保存且未过期的令牌（`~/.config/nwbd-dev-workstation/config.json`，权限 600）

**没有令牌或令牌过期时，脚本退出码是 2**，并在输出里说明需要重新复制。这时你应当：

1. 告诉用户去平台登录，在「用户信息」页复制访问令牌
2. 请用户把令牌贴到 **私密输入卡片 / secret 里**（不要让用户直接发在聊天里）
3. 用 `-Token <令牌>` 跑一次，脚本会自动保存，之后不用再给

**永远不要把令牌打印到对话、日志或命令回显里。**

## 平台地址

默认 `http://127.0.0.1:8092`（本地）。可用 `-BaseUrl` / `--base-url` 或环境变量 `NWBD_WS_BASE_URL` 覆盖；平台上云后，用户修改本地配置里的 `base_url` 即可。

## 错误码

| 退出码 | 含义 | 怎么办 |
|---|---|---|
| 0 | 成功 | — |
| 1 | 一般错误（参数不对、文件不存在、服务端报错） | 看输出里的「错误：…」，修正后重试 |
| 2 | 没有令牌 / 令牌过期 | 按上面「令牌」一节向用户索取新令牌 |

常见服务端错误：

- `403`：任务不属于当前账号，或没有项目经理权限
- `409 TASK_CLOSED`：任务已完成/已取消，不能再次执行
- `409 CONTRACT_REQUIRED`：项目没关联销售合同，产出不能归档，需先走 03 合同审批
- `409 PROJECT_NOT_READY`：文件管理里项目的目录还没建好，稍后重试
- `422 INVALID_FOLDER`：任务类型的归档目录在文件管理里不存在，找管理员核对目录模板
- `413 UPLOAD_TOO_LARGE`：文件超过 100MB
- `422 SKILL_REQUIRED`：任务没有绑定技能，先让项目经理在任务里绑定技能

## 操作规范

1. **先查再动**：用户说「开始做」，先 `show` 确认任务、状态和是否绑定了技能。
2. **只记关键节点（重要）**：平台页面每 10 秒自动刷新，用户会看时间线，但**不要写详细执行过程**。只在下面这些节点 `log`：
   - 开始执行时一条：说明打算怎么做（一两句）
   - 每完成一个**阶段性节点**一条（例如「大纲已生成」「初稿完成」「自检通过」），不是每改一个文件都写
   - 卡住或等待用户确认时一条：说明卡在哪、需要什么
   - 同一步骤只写一条，不要重复刷屏
3. **重复执行**：任务可能被多次执行。已完成的任务再点「重新打开并开始」会记成「第 N 次执行」，时间线按次数分组；重新开始时先看上一次的产出和结果，避免覆盖。
4. **上传前确认**：明确告诉用户要上传哪个文件到哪个任务，得到确认再执行 `upload`；同名文件先问是否覆盖。
5. **完成前确认**：`done` 之前把结果摘要念给用户确认，不要自行编造执行结果。
6. **进展要具体**：写实际做了什么，例如「已生成 12 页 PPT，等待用户确认配色」，不要写「处理中」。
7. **产出要真实**：只上传实际生成的文件，不要上传空文件或占位文件。
8. **不要绕过脚本**：不要自己用 curl 调接口，避免令牌泄露和参数错误。
