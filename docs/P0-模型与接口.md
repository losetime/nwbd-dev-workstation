# 研发项目管理系统 · 模型与接口（P0/P1）

本文件是 P0 的产物：把可点击原型里的业务结构固化成数据库模型与接口契约。
**原型是唯一业务基线**，说明书只作参考；两者冲突时以原型为准。

## 1. 与原型对齐的关键口径

| 项 | 取值 |
|---|---|
| 项目类型 | 合同实施项目 / 售前项目 / 自研项目 / 售后项目（**无外协合作**） |
| 阶段模板 | 合同 8：项目策划→需求分析→系统设计→开发实现→测试定版→交付试用→合同验收→整改结项；自研 6（到交付试用）；售前 3：需求对接→评估验证→持续跟进；售后 0 |
| 项目状态 | 未开始 / 进行中 / 暂停中 / 已结束 / 已取消 / 售后中（人工改） |
| 里程碑状态 | 未开始 / 进行中 / 已完成 / 已延期 |
| 任务状态 | 未开始 / 进行中 / 已完成 / 已延期 / 已取消 |
| 风险状态 | 监控中 / 已解决 / 已发生（原型口径，旧的识别/应对中已废弃） |
| 风险等级 | 高 / 中 / 低 |
| 风险类型 | 资源 / 进度 / 经费 / 客户 / 技术 / 其他 |
| 项目风险标识 | 高风险 / 低风险 / 正常（人工标注，独立于风险表） |
| 困难上报 | 严重程度：一般 / 较严重 / 紧急阻塞；状态：待PM查看 / 已登记风险 / 已忽略归档 |
| 项目角色 | 项目经理 / 软件开发 / 硬件开发 / 测试 / UI设计 |

## 2. 数据模型（9 张业务表 + 1 张审计）

原型用名称做关联，这里全部改为 **ID 外键**，名称只作展示冗余（原型第 3.5 节的硬要求）。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `app_user` | dingtalk_userid, unionid, name, title, dept, job_type, level, status, ui_perms, role, role_override | `title` 是钉钉职位原文；`job_type` 由职位映射而来；`job_type_manual` 标记管理员改过的岗位，同步不覆盖 |
| `project` | code, name, type, status, current_stage, risk_flag, contract_amount, budget, cost_actual, labor_budget, labor_rate, plan_doc_*, budget_doc_*, dt_contract_instance_id, contract_status, deleted_at | 编号唯一（可为空）；名称允许重复；软删除用 `deleted_at`；`dt_contract_instance_id` 关联 03 合同签订审批 |
| `milestone` | project_id, stage, plan_due, contract_due, locked, version | 立项时按类型模板生成；锁定后修改须走变更 |
| `project_member` | project_id, user_id, project_role, allocation, status | **项目经理也存这里**（project_role=项目经理），天然支持多人共管 |
| `task` | project_id, stage, owner_id, created_by, plan_*, status, estimate_hours, actual_hours, task_type, approval_instance_id, approval_status | 实际工时由工时确认累加；`created_by` 是下发人，决定谁能编辑任务内容；`task_type=项目策划` 时关联钉钉审批实例 |
| `task_skill` | task_id, skill_name, skill_version, sort_order | **一个任务可绑多个技能**，统一跟随技能库当前发布版本（`skill_version` 保留但恒为空）；`task.skill_name/skill_version` 为历史字段，仅保留不再读写 |
| `timesheet` | work_date, project_id, task_id, user_id, hours, rate, cost | 必须挂任务；同一人同任务同日期唯一 |
| `risk` | project_id, title, type, level, status, owner_id, identified_on | 状态三值 |
| `change` | project_id, type, source, content, impact, reason, budget_before/after, plan_due_after, material_path, approval_status, before_value, after_value, dingtalk_instance_id | 项目变更（05 项目变更申请）；`before_value`/`after_value` 记录变更前后快照，通过后写回项目预算与交付日期 |
| `issue` | project_id, task_id, reporter_id, severity, status, handling, risk_id | 困难上报；级别 高/中/低，状态 待处理/已转风险/已归档；可转风险 |
| `audit_log` | actor, action, target_type, target_id, detail | 审批、状态变更、锁定字段修改 |

## 3. 岗位映射（钉钉职位 → 岗位类型）

按顺序匹配，先命中为准：

1. 含「项目经理」→ 项目经理
2. 含「研发部经理 / 项目部经理 / 研发经理 / 技术经理 / 室主任」→ 部门经理
3. 含「测试 / QA / 质量」→ 测试
4. 含「UI / 设计 / 交互 / 美工」→ UI
5. 含「开发 / 工程师 / 程序 / 算法 / 前端 / 后端 / 研发」→ 开发
6. 其余（含职位为空）→ 其他

职位在登录与通讯录同步时刷新；管理员在系统管理里改过的岗位会打上 `job_type_manual`，不会被同步覆盖。

## 4. 权限

- **界面权限**：`myproj / pending / mytask / resview / myrisk / mychange / help / sysadmin`
- 个人 `ui_perms` 非空 → 以个人为准；为空 → 按岗位默认
- **数据范围**：部门经理看全部；其他人只看自己参与的项目
- **业务权限只看岗位，不看钉钉管理员角色**：`role`（钉钉主/子管理员）只用于标识，不授予项目编辑、建项目、换 PM 等业务权限
- **项目侧分工**：部门经理管项目（编辑信息、改状态、增退成员、换 PM、标记风险、新建项目）；项目经理只管自己项目的节点计划与任务下发；任务状态由**负责人**操作，项目经理不能在项目页点延期/完成
- **任务内容只有下发人能改**：`task.created_by` 记录下发人，只有下发人能编辑任务内容（标题、描述、验收标准、优先级、日期、预估工时、技能绑定），部门经理不是下发人时同样只读；负责人（研发）只能改状态、填工时、上传产出，改不了项目经理下发的任务内容
- **任务详情入口**：项目经理 / 部门经理在项目详情「③ 项目任务」点任意一行进入任务详情（只读视图，操作按钮按 `is_owner` / `can_edit` 收敛）；普通研发成员的任务行不可点
- **转派就在编辑里**：编辑任务时改「负责人」即转派，新负责人必须是本项目参与中成员；保存后写时间线「任务转派：A → B」，原负责人随即失去开始/工时/产出的入口。转派权随编辑权（仅下发人）
- **退出成员有前置检查**：该成员在本项目还有未完成任务（未开始/进行中/已延期）时，接口返回 409 并列出任务名，**一律不允许退出**（没有强制退出）；前端弹自建提示框（标题「提示」，只有「确定」一个按钮，点确定仅关闭提示），成员状态保持不变。项目经理也允许退出，不限制「至少保留一位」
- **风险管理**：项目经理 / 部门经理可登记与处理风险，研发只读；状态只有 监控中 / 已发生 / 已解决，转「已解决」必须填解决日期，已解决只有部门经理能重开；风险不删除；责任人必须是本项目参与中成员；项目「已取消」不能再登记。风险清单与项目风险标识 `risk_flag` 相互独立。左侧导航「风险管理」是跨项目总览（`/risks`，按参与项目过滤），登记与处理仍在项目详情「⑤ 风险管理」
- **困难上报**：独立页面「我要帮助」（`/help`），不进项目详情；所有岗位都可上报（部门经理可对任意项目上报），**处理只能归档（必填处理说明），不转风险**；可见与流转按上报人岗位走：研发/测试/UI 报的只到**该项目项目经理**，项目经理报的到**部门经理**，部门经理报的**只有自己能看到**；历史上已转风险的记录保留展示，不再新增
- **钉钉审批（04 项目策划流程）**：部门经理下发任务时可选「项目策划」，系统先调钉钉发起审批，成功后建本地任务并记录实例 ID；钉钉失败则任务不落库，提示重试；本地落库失败自动撤销审批。审批状态由 Stream 消费者实时回写，另有手动接口兜底。关键传值：联系人控件传 `["userId"]`，关联审批单（项目代号）直接传实例 ID 字符串
- **合同审批自动建项目**：03 销售合同签订审批通过后，消费者自动建项目（编号=项目代号可空、名称=合同名称、客户=甲方单位、金额=合同金额、状态未开始、关联合同实例）；合同撤销/拒绝时在项目上打标，不删除数据；项目名可改、允许重名
- **变更管理**：本项目项目经理 / 部门经理可发起「05 项目变更申请」；先发起钉钉审批、成功再落库；审批通过后自动把「变更后预算 / 交付日期」写回项目，并在 `change.before_value/after_value` 与审计日志中留变更前后记录；撤销在钉钉操作，系统只同步状态
- 关键动作服务端二次校验：新建项目、编辑项目、上传附件、管理人员、登记/处理风险、处理困难的接口都按角色拦截

## 6. 计算口径

全部集中在 `backend/internal/metrics`，有单测：

- 任务完成率 = 已完成 ÷ 任务总数（不含已取消），无任务返回 null
- 任务逾期 = 未开始/进行中/已延期 且 计划完成日 < 今天（当天到期不算）
- 里程碑超期 = 未完成 且 截止日 < 今天（计划超期、合同超期分列）
- 延期完成天数 = 实际完成日 − 计划完成日
- 建议工时 = 预估工时 ÷ 区间内工作日数（保留 1 位小数），最后一天补差额；本次可填 = max(建议 − 当天已报, 0)

### P2 实现说明

- **编辑信息**字段与原型一致：客户、合同金额、计划起止、预算、备注（另加人力预算与费率）；编号/名称/类型不可改。
- **节点计划**按原型「首次填写不锁定」：已锁定行只读，锁定动作留给 P4 的变更模块。
- **里程碑状态改成「进行中」**会自动把项目当前阶段推进到该阶段。
- **更换项目经理**会把移出名单的人标记为「已退出」，记录永久保留。
- **删除项目**按约定不做，项目用状态「已取消」结束。

### P3.1 任务看板（参考 nwbd-automation-demo）

任务从「一行表格」升级为可跟踪的工作单元：

- 任务字段新增：描述、验收标准 `acceptance[]`、优先级 `P0/P1/P2`、标签 `tags[]`、链接 `links`、结果摘要、完成时间、`skill_name/skill_version`
- 新增 `task_event` 表：下发、状态变更、进展记录、完成都会写一条时间线
- 页面：`/tasks`（统计卡 + 状态页签 + 搜索 + 卡片网格）、`/tasks/:id`（描述 / 验收标准 / 技能 / 产出 / 工时确认 / 时间线 / 执行结果）
- 状态沿用项目口径（未开始/进行中/已完成/已延期/已取消），「待办」即「未开始」
- 权限：负责人、本项目项目经理、部门经理可编辑与流转；「已取消」仅项目经理/部门经理

### P3.2 技能执行与工时确认

**技能**：服务端代理线上技能库 `nwbd-skills`（默认 `http://8.160.178.247:18138`），前端不直连；任务可绑定 `skill_name + skill_version`，不填版本则跟随最新。

**执行**：任务分配给谁，就由谁在任务详情点「按技能开始执行」。

- 写 `task_run`（执行人、技能、版本、开始时间、状态）
- 任务置「进行中」，时间线记一条 `claimed`
- 执行过程用「记录进展」回写时间线；可随时上传产出到 `task_artifact`，文件本体存文件管理（`nwbd-file-manage`）
- 「完成并提交结果」写结果摘要、结束 `task_run`、任务置「已完成」，时间线记 `done`

**工时确认**：

- 按任务计划区间与预估工时生成每日建议（只摊工作日，最后一天补差），自动扣减当天已报
- 确认后写入 `timesheet`（同人同任务同日期累加），并累加任务「实际工时」
- 折算费用 = 工时 × 项目人力费率（未设置按 0）
- 确认日期必须落在任务计划区间内
- 口径实现在 `internal/metrics`，有单测

**新增表**：

| 表 | 说明 |
|---|---|
| `task_run` | 一次技能执行：执行人、技能、版本、状态、摘要、起止时间 |
| `task_artifact` | 任务产出物：文件管理文件 id、最终文件名、归档目录、大小、上传人 |
| `task_type` | 任务类型字典：编码、名称、归档阶段、归档目录、说明（33 项项目任务） |

**产出归档（文件管理）**：

- 任务创建时把任务类型的归档目录快照到 `task.archive_folder`，历史任务不受字典调整影响
- 上传前用 `project.dt_contract_instance_id` 调文件管理 `GET /internal/projects/by-instance/{id}`，换取项目 id 与一级目录
- 上传走 `POST /internal/projects/{id}/files`（`X-Internal-Token`，multipart），文件名由文件管理统一加 `_yyyyMMddHHmmssSSS`
- 任何一步失败都直接报错、不写产出记录；文件已上传但本地入库失败时调 `DELETE /internal/files/{id}` 回滚
- 没有关联销售合同的项目不允许上传产出（`409 CONTRACT_REQUIRED`）
- 下载由本系统代理 `GET /internal/files/{id}/download`，内部令牌不出服务端；时间线记一条 `artifact` 事件，任务产出区单独展示产出时间线
- 配置：`FILE_MANAGE_BASE`（容器内 `http://nwbd-fm-api:8000`）、`FILE_MANAGE_TOKEN`；api 容器加入 Docker 网络 `nwbd-link-files-dev`

**状态实时可见**：

- 任务详情页：状态为「进行中」时每 10 秒轮询一次（页面隐藏时暂停）
- 任务看板：每 10 秒轮询一次
- 接口返回 `last_event_at`（最后一条时间线事件时间）与 `stalled`（进行中超过 15 分钟无事件 → 可能已中断）
- agent 侧只记关键节点：开始、阶段性完成、卡住时各一条 `log`，不记录详细执行过程

**第 N 次执行**：

- `task.attempt_count` 记录执行次数；`task_event.attempt` 标记事件属于哪一次
- `POST /api/my/tasks/{id}/start`：未开始/已延期 → 开始新一次；已完成/已取消 → 重新打开并开始（`reopen`），`finished_at` 清空，结果摘要保留
- 时间线按次数分组：第 N 次执行 / 任务建立
- 任务允许多次执行，不做防重复
